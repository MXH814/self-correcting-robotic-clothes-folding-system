## 1 评分目标与整试次指标

候选评分仍使用`conditional_full_task_success`语义。其目标是：从决策时刻起执行候选，并在固定接续控制器、目标与剩余预算下，最终完成且质量通过，同时不再发生新的求助或人工介入。模型必须针对该条件和输入范围获得校准证据。

整试次`autonomous_success`继续按AI03记录，从任务开始保留全部求助/介入；历史已经发生的事件不能撤销。后续评分不修改该指标。以下为定义例子，均不是实验结果：

| 既往求助/介入 | 决策后的结果 | 延续目标 | 整试次自主成功 |
| --- | --- | --- | --- |
| 无 | 完成且质量通过，无新增求助/介入 | true | true |
| 有，之后合法人工返回 | 完成且质量通过，无新增求助/介入 | true | false |
| 任意 | 后续再次求助/介入，或完成/质量判定失败 | false | false |
| 任意 | 完成/质量证据不足且无已知失败条件 | unknown | 按实际完整证据判定；不能伪填成功 |

若某一必要条件已知为false，合取目标为false；只有尚未被否定且关键证据缺失时才是unknown。局部重抓成功不能填充最终质量，也不能把未执行候选填成失败或成功样本。

当前诊断schema仍保留整试次`autonomous_success`，用于**没有既往求助/介入**的根状态；在此范围内，当前后续目标与整试次指标一致。人工返回后的根状态暂不混入现有监督比较：须新增明确的决策边界、后续求助/介入、最终证据及标签版本后，再扩展训练/校准。不能只改列名就宣称已具备监督或泛化能力。data2/data3均为无恢复标签的正常观测，不进入该比较。

## 2 旧代迟到结果与连续不可用计数

连续不可用计数按`task_id + control_generation`维护；代次变更初始化当前计数，不清除恢复尝试、已用预算或历史审计。接收结果先核任务/代次，再去重和归类：

- 旧代结果：仅写审计及对应T18记录，不改变当前计数、当前任务状态或授权。
- 当前代重复结果：返回已有处置，不重复计数或计次。
- 当前代不可用结果：按SRS既有规则处理连续计数；需要立即停止/求助的原因仍按对应规则处理。
- 当前代有效可用决策：结束该次连续不可用序列；是否派发仍需完整门禁。

反例走查：暂停前worker在恢复后返回，不能成为新代的“第3次不可用”而导致额外停止；重复传输同一超时事件也不能被算成多个独立决策。此为预期行为，尚未证明真实协调器实现遵守。

## 3 adapter代次屏障与静止证明

仅对command ID去重不充分：旧代命令可能首次到达时，halt已经先到且设备已经报告静止。接纳和执行端必须知道哪些代次已撤权。

设计顺序为：协调器原子撤权/提高代次，通知adapter安装单调屏障；adapter拒绝旧代新到命令并清空或取消旧队列，报告屏障已生效；再结合SRS规定的当前新鲜速度窗口、空队列和无活动片段形成静止证明。屏障的代次、最后命令及测量证据关联保存。ACK、取消Future、空队列单点或进程退出均不能单独替代该证明。

如果使用有序传输/排空协议作为替代，须证明相同保证，包括重连、重复、乱序、首次迟到命令和应用重启，不能仅写“TCP有序”即通过。执行前仍须复查授权与屏障；具体测量及T02/T04/T07/T18由真实adapter联调验证。
