# ADR-MA-002 · 历史与整任务延续评分先诊断、后选型

状态：Accepted as implementation baseline，2026-11-06；依据组长授权采纳诊断优先与可替换接口，队友可审核修订。研究假设仍待证，不代表训练选型或性能已通过；见[执行决定](../../research/ma-owner-decisions.md)。

## 问题

本项目关注部分折叠失败后的恢复。已有工作覆盖候选排序、Q 引导和失败动作纠正；尚不能把这些模块的组合认定为创新。需要区分观测不足、候选不足和排序不足，避免在数据不可用时锁定昂贵网络。

## 备选比较

| 方案 | 优势 | 风险/取舍 |
| --- | --- | --- |
| 固定规则＋简单阶段条件评分 | 易验证、低成本、清楚的工程对照 | 泛化受限；概率解释仍需校准 |
| 当前视觉/阶段＋简单最终结果预测 | 可检验 H2，复杂度适中 | 部分观测/标签噪声可能限制能力 |
| 历史编码＋候选延续评分 | 可检验 H1/H2 | 输入/容量/预算容易不公平，历史未必必要 |
| 世界模型＋VLM叙述/校准 | 通用语义推理、明确拒绝机制 | 预测/叙述误差、模型成本与隐私部署复杂 |
| 完整 RedFlow 式离线 VLA 后训练 | 利用混合 rollout，已有叠衣近邻 | 数据覆盖、上下文匹配和训练资源要求较高 |

## 拟议决定

固定正常控制器和候选接口，先实施规则与简单阶段基线，按 H1/H2 诊断决定是否增加历史/延续模型。生成与评分可替换，研究代码不成为 UI/任务启动依赖。复杂方法作为最近邻比较或后续候选，未选定算法写为暂定，不能宣传性能。

保持 SRS 的历史条件恢复/最终结果目标；若诊断决定删除某能力或改变算法需求，应提交变更并记录理由，本文不直接改 SRS。固定目标下不新增自然语言歧义工作流。

## 证据、验证与重审

依据 [比较矩阵](../../research/related-work-matrix.md)、[H1/H2](../../research/hypothesis-cards.md)。预先用同候选池区分候选上限和选择性能，匹配数据/容量/预算；整任务标签含接续控制器与剩余预算，局部指标单列。

H1 被阶段/容量解释则简化；H2 无冲突则取消复杂延续预测；候选全无效则改生成而非继续堆排序；明确学术新颖性不足时重新检索/调整问题。团队 Design 仍用可替换接口与 PoC 完成，不等候“创新成功”。
