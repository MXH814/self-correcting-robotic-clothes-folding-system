# ADR-MA-004 · 采用已有Isaac Sim / DexGarmentLab开发环境

状态：Accepted as development baseline，2026-11-06。组长授权下采纳，队友可审核；不是P02/E02/SRS环境验收通过。依据[分支审查](../../reviews/zhang-bc5e48c-review.md)及已合并的[环境报告](../../research/zhangmingbo/environment-feasibility.md)。

2026-11-08安排更新：马祥珲确认已在张电脑完成基础复跑，基础项关闭；后续仿真/采集/恢复闭环统一使用该电脑，不要求组长本机安装或换机复跑。固定环境材料用于现有环境记录/恢复，见[执行安排](../../research/shared-simulation-workflow.md)；新接口、停止和恢复实验继续分别验收。

## 选择与替代方案

采用张茗博已运行的Isaac Sim 4.5.0 / DexGarmentLab / UR10e+Shadow Hand / Fold_Tops作为首选开发栈。保留其低资源配置及准确归档hash；恢复算法在独立进程/逻辑接口后，不依赖UI中的具体机器人维数。

替代A：重新搭建其他布料平台。优点是可选简化动作；代价是资产、物理和正常控制重复投入。APS-Net的SoftGym/FleX路线尚未核实可直接复用的代码/权重，不为追求论文名字而迁移。

替代B：立即租A800并完整重训HALO。可能加快训练，但没有镜像/图形能力兼容、报价、吞吐和完整资产证明；一次复制作者大规模训练并不直接验证我们的恢复gap，因此当前不采用为前置。

## 技术与部署

- 张的仿真运行环境是独立Isaac Python 3.10；本仓库离线工具可在Python 3.9+运行。两者隔离依赖，以带版本文件/消息接入，不能覆盖Isaac自带Torch/NumPy来迁就分析脚本。
- 当前部署以一台受控仿真工作站为基线，UI/协调器可以逻辑独立；远程GPU仍为待验证替代部署，不声称服务、网络、停止已经联通。
- 论文动作和本地测试报告提示双手臂/手共60通道，但名称、顺序、单位、边界与控制模式必须由真实profile确认。论文维数不能直接变成可派发命令。
- 官方GAM/示范流程可作小范围正常控制候选，冻结版本并单独报告成功判据；示范流程不能标成HALO策略评估。

## 接受和重审条件

可在已知环境上继续开发，但自主动作前必须有完整动作/观测profile、停止回执、来源核验与预算监控。恢复实验前要有正常轨迹、两类真实生效失败、合法候选及重置误差。质量依据SRS，官方True仅作上游诊断字段。

RAM兼容检查失败及接触缓存修改列风险：重复试跑测实际占用/发散，不能以单次通过证明稳定。资产许可无法满足、稳定布料/观测/停止无法建立、成本不可承受则重审。更换平台、任务或产品能力需更新需求与设计，不偷偷修改SRS阈值。
