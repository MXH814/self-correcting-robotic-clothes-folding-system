### 主持人怎样推进同一场景

参与者操作产品区，你只操作测试桩。先让对方回答，再记下能否独立辨认当前状态；避免告诉对方应点哪一个按钮。对方明确求助或准备放弃时，可问“你现在希望系统做什么？”；如需指路，逐字记下提示及发生时间。主持人模拟设备回执属于场景操作，另记其等待，不算参与者求助。

| 任务 | 主持人操作 | 观察依据（不向参与者展示） |
| --- | --- | --- |
| 1　开始 | 读完任务 1、交给参与者操作时启动秒表。对方发出有效启动请求时记分段时间，立即点测试桩“校验通过”；监控页首次出现“折叠中”时停该任务计时。 | 能否找到准备条件、就绪检查和启动；能否辨认运行状态。记录墙钟总秒、主持人等待秒及错误，不把主持人等待默默扣除。2 分钟仅作设计对照。 |
| 2　异常与停车 | 注入“部分滑移”，停下来听其辨认“恢复中”。对方暂停后，点“设备正在停车”，先问现在能否调整，再“提交本代静止证据”。让其自行申请协助。 | 是否区分任务已暂停、设备正在停车、已确认静止及等待协助；能否从监控页找到求助入口。 |
| 3　调整与归还 | 让其在协助页自行接管、调整并归还。第一次归还后提交本代静止证据，点“校验失败”；待其再次接管、修正并归还后，再提交新静止证据，点“校验通过”。 | 是否在获得权限后才调整，能否看懂归还失败原因、重新接管，最终确认返回“折叠中”。第一次归还失败是统一安排的情景，勿记为用户错误。 |
| 4　结果 | 回到折叠后，点“观测到折叠目标”及“提交本代静止证据”；在结果页点“质量：通过”。请对方完成任务 4。 | 是否分别读出运行完成、质量通过、有人工帮助、未计自主成功；能否用回放找出依据。 |

中途若误终止、跳过或退出，按实际落点记录；如需刷新或主持人恢复场景才继续，把后续标为“辅助继续”。首轮记录保持原样。每人结束后记录其最想改的一处及原因。真实发布、模型训练和维护者权限均不属于本次家庭用户走查。

### 五屏设计理由

| 屏幕 | 用户要决定什么 | 本版设计理由 |
| --- | --- | --- |
| S01 准备任务 | 现在能否开始？ | 先检查衣物、桌面与设备状态，再受理启动请求。把“取消请求”放在校验阶段，便于用户退出而不产生任务结果。 |
| S02 运行监控 | 当前能暂停、继续、求助还是终止？ | 同屏列出任务态与设备态，使用户能看到“已暂停／正在停车”同时成立；次数、活动时间和费用均属模拟任务。 |
| S03 人工协助 | 当前谁有权调整衣物？ | 显示控制权、求助原因和停车状态。归还时立即撤回手动权限；越界时给出移回桌内的修正办法。 |
| S04 结果与回放 | 如何从过程证据解释结果？ | 四项判定分列。事件选择器按任务内序号跳转，配合只读播放复查接管和归还。侧栏真实记录使用单独播放器，避免将两条正常轨迹误配到模拟接管事件。 |
| S05 模型与配置 | 维护者能否为下一次任务更改设置？ | 由角色、已确认静止、空闲状态及训练／验证证据控制入口。保存前检查单位与范围，错误时保留先前配置。 |

已用 Chrome 复验键盘启动、部分滑移、暂停与确认静止、归还失败后再次接管、归还通过、模拟质检通过但自主成功为否、按事件跳转，以及真实 RGB 播放器的独立性。真实用户需按上表记录实际观察。张茗博负责真实状态、权限与停车证据，马祥珲核对恢复和质量语义；现场展示方式、真实联动深度及真实日志配对待组长确认。
