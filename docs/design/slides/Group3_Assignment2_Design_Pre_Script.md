## 第1页 自主纠错型机器人叠衣系统

讲解人：胡知鱼    建议用时：10秒

大家好，我们是第三组。本次介绍自主纠错型机器人叠衣系统的架构、设计取舍，以及已经完成的仿真和检测验证。

## 第2页 用户需求与项目范围

讲解人：胡知鱼    建议用时：25秒

系统面向需要机器人叠衣的使用者，维护者负责配置和模型管理。普通使用者只需要准备衣物、启动任务，在系统求助时接管。我们把范围限定为固定桌面上的一类仿真上衣，重点处理抓取偏移和部分滑移。关键问题是，发生异常后如何有依据地决定继续、恢复还是求助，同时避免把计划释放误认为故障。

## 第3页 五屏原型与人工接管

讲解人：胡知鱼    建议用时：30秒

我们已经把需求落实为五屏交互原型，包括准备、监控、协助、结果和维护。这里展示的是实际原型的协助界面，采用测试事件验证交互。暂停请求只撤销自动派发权限，还必须获得静止证据，用户才能接管。用户归还控制权后，系统重新校验场景和阶段。回放只读，不能恢复控制权限。这个界面目前还没有接入真实仿真控制。

## 第5页 逻辑架构与控制权限

讲解人：张茗博    建议用时：40秒

逻辑架构的中心是任务协调器。界面提交请求，观测网关接收带来源和时间的图像与测量，检测恢复模块提出诊断和候选动作。只有协调器可以批准派发，仿真适配器负责执行和测量反馈。记录模块保留提案、接受、执行与结果，离线训练只输出有版本的模型。这样的设计使模型可以替换，又能统一处理过期结果、预算与人工接管。图中是设计职责，已完成的软件和实际仿真验证范围将在后面单独说明。

## 第6页 部署架构与技术选择

讲解人：张茗博    建议用时：35秒

当前部署基线是张茗博的工作站。Isaac Sim 4.5 和 DexGarmentLab 在独立 Python 环境运行，正常折叠使用已有 GAM 加脚本流程。检测采用 PyTorch 和固定 ResNet18 编码，浏览器运行交互原型。原始 RGB、关节和动作记录与小型元数据分开保存，通过指纹关联。我们优先使用本地已验证环境，减少远程渲染、时钟和依赖冲突。跨进程通信和存储引擎保留为后续验证决策，同机 GPU 争用也需要测量。

## 第7页 关键决策与取舍

讲解人：张茗博    建议用时：30秒

我们比较了三项关键选择。第一，协调器统一授权，模型只提候选，代价是增加检查开销。第二，复用FIPER观测分支，按过去正常命令区分左右袖，避免依赖尚未获得的生成式动作采样。第三，恢复后限定左袖接续同时检查新几何，保留原始视觉告警。这样可以验证固定场景的接续，但依赖仿真内部信息，不能外推成纯视觉能力。完整试次划分和所有开发用途变更均保留。

## 备份问答

### 检测和恢复实际做到了什么程度

当前已出现一次RGB告警驱动前检、五步宏、宏后新窗口复检以及接续折叠的开发实跑。完整A/B原始RGB与冻结checkpoint已共享，A465次、B493次记录调用（含一次前检刷新）独立重算，状态、原因和阈值一致。产品级协调器、正式质量及统计成功率仍需对应验证。

### 为什么说是复用FIPER而不是完整复现

原文同时使用观测嵌入RND和生成式动作熵。现有正常控制是GAM加脚本，没有匹配动作分布样本。本组复用其观测网络，替换固定ResNet18特征，并采用自己的窗口、阶段阈值和诊断接线，不继承原文的完整判别能力或统计保证。

### 几何检查是否等于视觉检测

不等于。初次告警来自RGB。宏后持有和限定左袖接续使用声明的仿真内部材料片与指尖几何。原始视觉报告保留，策略允许在新鲜HELD几何支持下限定接续。正式质量或实物感知需要另验。

### 区域比例能否当成恢复成功率

这是本次最终点云落在目标区域的比例。它不是多次实验的恢复成功率，也不替代SRS的折叠地标、质量或自主完成判据。

### 32毫秒和63毫秒是否说明系统实时

这是已有日志中的检测调用内处理中位数和最大值，模型已加载。未包含未测曝光、系统队列、界面与产品停车链路，不能当作完整系统实时性通过结论。

### 可见异常起点如何判断

胡的画面技术判读把B投影分离限定为6.683至6.883渲染秒。开手注入发生在5.983秒，首报警图像在7.033秒，这三者意义不同。远景投影不能定位物理接触消失首帧，暂不据此报告正式检测延迟。

### 这次作业是否都要实现

作业重心是从Part I需求形成可指导实现的设计，覆盖三类架构、模型、关键决策理由、需求变化与风险。现有实现和实跑支撑设计可行性。最终九项材料、成员确认、实际课堂反馈和提交回执仍须逐项完成。
