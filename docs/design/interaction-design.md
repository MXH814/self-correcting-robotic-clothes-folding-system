# 五屏原型交互说明与复验

双击仓库中的 [`prototypes/ui/index.html`](../../prototypes/ui/index.html)，用 Chrome 或 Edge 打开。保留 `app.js` 和 `style.css` 的相对位置。首次打开处于家庭用户的准备页，设备已有一份示例静止证据。页面上半部供操作者使用；下方“测试桩”由演示者代替相机、控制器和审核流程返回事件。停在“校验中”或“等待停车”时，下一步就在测试桩内。

**建议先演示一次有人工协助的折叠。** 勾选两项准备条件，依次点击“检查就绪”“开始折叠”，再让测试桩返回“校验通过”。在运行页注入“部分滑移”，暂停后提交本代静止证据，点“请求协助”。在协助页接管、调整、归还，再提交**新的**静止证据并通过校验。回到运行页，依次触发“观测到折叠目标”和“提交本代静止证据”。在结果页给出示例质量“通过”。此时应能同时看到“运行完成”“质量通过”“使用过人工协助”“示例自主成功：否”。拖动回放滑块可定位每个操作当时的状态。

## 五屏如何对应需求

| 屏幕 | 谁在这里做什么 | 沿用的约束与本次实现 | 需求基线 |
| --- | --- | --- | --- |
| S01 准备任务 | 家庭用户确认一件展开、无结的上衣，桌面无杂物并理解协助步骤 | 保留固定衣物与目标。场景过期、衣物配置不匹配、未静止、有活动任务时均锁定启动。就绪检查后才可发出启动请求；等待期间可取消，拒绝或取消均不生成任务。通过时分配任务编号并冻结配置、模型、种子。 | UC01；FR01–02；DR01 |
| S02 运行监控 | 查看折叠或恢复状态、次数、活动时间、模拟费用和设备状态，决定暂停、继续、求助或终止 | 同一任务共享次数和预算。每次接受纠正动作才计数。恢复中暂停会记住原状态；停车确认及继续校验通过后返回恢复中。终止须确认，优先于迟到的策略结果。 | UC02–04、UC06；FR03–07、FR09；DR02–05 |
| S03 人工协助 | 查看求助原因、剩余次数和计费情况，接管、调整、归还 | 提出求助后先等待静止证据；只有确认静止且显式接管，才开放手动调整。归还立刻撤回手动权限，新停车证据及 DR05 校验均通过后才恢复自动运行。归还失败会指出衣物越界，回到等待协助。 | UC05–06；FR07–09 |
| S04 结果与回放 | 家庭用户选择本会话自己的已结束任务，查看、播放、导出或删除记录 | 运行结论、求助、接管、质量、示例自主成功分别展示。回放是按操作顺序生成的事件与桌面示意图，可播放、暂停、跳转。导出当前记录为 JSON；删除需二次确认，有数据引用或当前任务停车未决时锁定。空列表说明何时才会有结果。 | UC07、UC12；FR10–11、FR16；AI02、AI07 |
| S05 模型与配置 | 维护者登记示范批次、批准作业预算、走完模拟训练与验证、读取一次封存终测并激活候选 | 家庭用户不可进入。待启动或活动任务、停车未决时禁止修改。缺少训练或验证证据、终测失败或接口不兼容时禁止激活。配置字段按单位、范围和步长校验，错误时保留旧版本。 | UC08–11；FR12–15；AI04、AI06 |

## 为什么拆开任务状态和设备状态

“已暂停”表示系统已经停止派发自动动作，机械臂还可能在减速。原型分别显示任务状态和设备状态；点击“设备正在停车”只更新设备状态。点击“提交本代静止证据”代表示例适配器已检查当前代号、实测静止和空队列，才解锁继续或接管。终止先固定任务结论，停车超时仍须锁定新的启动、手动动作和模型激活。

初始校验失败返回准备页；暂停后的校验失败保持暂停；归还后的校验失败返回等待协助，必须重新接管。三条路径都能在浏览器里触发。活动仿真时间与模拟 GPU 分配时间分别累计；已静止的暂停不消耗活动时间，资源仍分配时会继续计费。默认预算沿用三次恢复、300 活动仿真秒和 0.25 美元，费用按示例费率 1 美元/小时换算。

## 本地复验记录

以下路径已通过 Chrome 从本地文件入口点击验证。每条可用刷新恢复默认示例。表中的点击名称对应界面或测试桩，除准备类用例外均从已启动任务开始。

| 检查点 | 复验操作 | 已观察到的结果 |
| --- | --- | --- |
| 启动与空状态 | 注入相机过期或衣物不匹配；切回有效，分别取消启动、返回校验失败 | 错误场景锁定启动；取消和失败后均无新任务或结果 |
| 有限恢复 | 连续注入三次部分滑移，再注入抓取偏移 | 次数停在 3；转到等待协助，接管与归还后仍沿用原任务 |
| 暂停与过期返回 | 抓取偏移 → 暂停 → 正在停车 → 送达旧代动作结果 → 提交静止证据 → 继续；先使校验失败，再继续并通过 | 停车前“继续”禁用，旧代结果丢弃。失败回到暂停，通过后恢复原“恢复中”状态，已用次数仍为 1 |
| 归还失败 | 确认暂停并求助 → 接管 → 调整 → 归还 → 新静止证据 → 校验失败 | 归还期间手动操作锁定；失败回到等待协助，重新接管、调整、归还并通过才返回折叠 |
| 完成与质量 | 观测到目标 → 静止证据 → 离线质量通过；比较有、无求助两条路径，再输入质量未通过 | 有人工介入的完成记自主成功“否”；无求助的合格示例只有质量通过时为“是”。更改质量不改写运行终态 |
| 回放与引用 | 选择完成记录、下一事件、添加示例引用；解除引用后确认删除 | 回放显示历史事件；有引用时禁止删除；删除唯一记录后显示空状态 |
| 两类失联 | 控制会话失联 → 静止证据 → 重新认证并绑定 → 显式继续并通过；再注入设备适配器失联并恢复链路 | 前者保留暂停任务；后者使活动任务失败。链路恢复后仍锁定执行，必须取得新证据 |
| 决策及停车超时 | 过期观测一次、决策超时两次，进入求助后触发停止确认超时；另起任务先终止再触发同一超时 | 连续三次无效触发求助；未结束任务停车超时变为失败。已经终止的任务保留终止结论 |
| 等待中的成本 | 暂停 → 确认静止 → 模拟计费额度耗尽 | 即使没有继续派发动作，任务仍以计费额度耗尽结束，并请求停车 |
| 维护门禁和版本冻结 | 切维护者，依次登记、批准预算、训练、验证冻结、读取终测；注入接口不兼容，再恢复兼容并激活；活动时间上限先填 0 再填 240 | 不兼容时禁用激活；非法配置不产生版本。新任务冻结新模型与 240 秒配置，任务进行中禁止保存配置 |

另已检查脚本语法，并检查 390 像素宽视口的维护页无水平溢出。以上为本地界面行为复验，课程 T01–T18 的系统验收、真实用户走查和实际仿真计时另行取证。

## 复用来源与实现边界

- **原型。** 远端五屏的任务顺序、标题含义、角色、控制项和默认预算作为设计起点。每一屏底部可展开对应的第一阶段英文 SVG 原稿。本版将原稿中“点击看说明”的方式改为共享任务状态、来源相关的校验和可回放记录。[远端原型](https://github.com/MXH814/self-correcting-robotic-clothes-folding-system/blob/4191e8f5d9f065dd009367f83572693141c4d551/prototypes/ui/index.html)
- **需求。** 按远端第一阶段计划的交互条目和课程清单 A2-05 核对。页码按本地最终英文 SRS：第 19 页为模型激活，第 21–25 页为执行和停止规则，第 29、32 页为校验来源与失联，第 35 页为自主成功，第 39–43 页为五屏。远端与本地 SRS 文件对象标识不同，本文引用本地页码；与远端计划、远端原型已核对的规则见上表。[第一阶段计划](https://github.com/MXH814/self-correcting-robotic-clothes-folding-system/blob/main/docs/first-stage-plan.md) · [课程清单](https://github.com/MXH814/self-correcting-robotic-clothes-folding-system/blob/main/docs/assignment-2-checklist.md) · [最终 SRS 目录](https://github.com/MXH814/self-correcting-robotic-clothes-folding-system/tree/main/submissions/assignment-1/Group3_Assignment1_SRS)
- **演示假设。** 一个家庭用户和一个维护者用同一浏览器演示；切换角色模拟权限，重新绑定模拟会话认证。记录保存在内存中，刷新后清空，需要留存时先导出。桌面图只表示阶段，示例质量由测试桩给出。研究试次的合格性在自主成功示例中预设为合格。运行、训练、终测、收费、网络时限和静止证明都由离散事件驱动。真正的身份校验、持久化、停止证据验签与测量、按真实时钟计费、模型质量和系统联调仍需后续验证。


**2026-11-08 接口复验。** S02 和 S03 的“接口原因码及处理说明”可展开查看。开始任务后分别注入过期观测和决策超时，再点“重送上一条决策回复”和“送达旧代动作结果”。此时仍应折叠中，连续不可用计数为 2；下一条本代独立超时才触发求助。可另开一轮在第二次超时后暂停、确认停车、继续并通过校验，再送旧代回复，检查新代计数仍为 0。S04 导出显示 source=synthetic 及任务内连续序号，回放历史提示保留触发码。暂停后迟到回复不得恢复执行。接口表注明哪些原因仅有说明，供集成时补设备证据。[原因码与导出字段](ui-contract.md)
