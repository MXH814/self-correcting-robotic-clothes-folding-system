## 原始证据与复算

[下载团队私有证据ZIP](https://github.com/MXH814/self-correcting-robotic-clothes-folding-system/releases/download/zhang-garment-observation-20261108/full-fold-recovery-chain-20261108.zip)。文件大小及SHA-256见 [package.json](package.json)。包内 [manifest.json](manifest.json) 绑定每个原始文件；仓库这里只保存小型索引，完整图像、数组和trace在ZIP中。打包后已逐文件检查CRC、大小与SHA-256。

解压后在仓库根目录执行；第二个路径必须是证据目录外尚不存在的输出目录：

```powershell
python tools/simulation/verify_fold_recovery_chain.py <解压目录> --output <新的审核输出目录>
```

校验器复用既有因果输入与17维宏编码，检查同次ID、提案指纹和可用时刻、决策源观测、完整宏执行顺序、实际派发/反馈、接续与最终点云。输出 `pending-review.json` 的schema为 `recovery-chain-pending-review/1`，有一份完整宏候选特征，明确不冒充 `reviewed-recovery-sample/1`。原始未来结局与离线网格不会进入视觉/关节特征。

复跑本次入口：

```powershell
powershell -ExecutionPolicy Bypass -File tools/simulation/run_local.ps1 -Stage fold-recovery -FoldRecoveryCondition early-open -Headless -OutputRoot <新的采集目录>
```

此入口仍会按上游规则在实验机 `Data/Fold_Tops` 生成新的轨迹/最终图，不覆盖旧轨迹。新证据另有独立目录和试次ID。启动器只有在最终结局、完整trace及文件清单保存后才写完成标记；宏移动失败会中止，不执行后续宏操作或接续，也不自动补成负标签。

## 相机、上下文与剩余审核

本批固定相机显式朝向桌面，640×480 RGB，补充1000强度的DomeLight；在第一个折叠动作前固定姿态、镜头并预热12个物理步，检查非全黑图像。观测每3个物理步采集一次，并在决策/阶段边界补采。相机位姿、内参、步长、控制器及采集源码SHA-256、目标定义和一次宏预算均在上下文中。它不同于 #18 的240×180固定视角，也不同于 #22 的移动近景，不直接混为统一训练配置。

释放和闭手分别额外等待45、12物理步；这些等待在上游手势方法内部步进之外。只允许一次诊断宏，无重试；产品权限、DR04完整约束、停止/求助和正式费用预算未接入。目标仍是已命名的官方区域代理；最终SRS验收不能由本次True替代。

当前上下文以本次文件指纹绑定。合并多次监督样本前，马需审核并冻结共享的控制器、目标、预算、相机和预处理版本；本批不自动分配train/development。胡需独立确认本次局部/最终或未知标签及证据，#22 的肩/下摆映射与预期夹持定义审核继续独立进行。后续再扩候选及正负/未知结局覆盖，不把一条通过的官方代理结局当作已具备训练集。
