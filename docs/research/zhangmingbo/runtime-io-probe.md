# 运行时 I/O 采集：组件探针及实测

已在本机采集并核对组件级关节 profile、命令、反馈和仿真 RGB。完整折叠场景、协调器 ACK 和停止反馈仍待验证。

## 尝试结果和下一步

2026-11-08 在张的 Windows 实验机启动一次 headless 采集，启动前物理可用内存约 2.9 GiB；启动期间检查到物理可用约 1.09 GiB、虚拟可用约 0.75 GiB。为避免影响当前工作，主动停止了本次启动的 Isaac Sim 进程；启动日志到达 `Simulation App Startup Complete`，但未生成样本。该次人工停止不能证明程序成功或失败，也不能单凭它确定卡顿根因。停止后物理可用约 4.06 GiB，虚拟可用约 6.76 GiB。这些是当时瞬时读数，不是最低运行配置或资源需求测量。

用户随后要求重试：首次重启加载了双臂和相机但无样本；增加阶段日志后发现代码错误——`SingleArticulation.dof_properties` 的类型文字说明与实际枚举不一致，而该属性代码在本版本取了首项类型并广播。脚本改为从 articulation view 逐关节读取实际类型后，第三次启动生成下述记录。一次采集过程中观察到约 0.94 GiB 虚拟内存，退出后回升至约 8.57 GiB；这些瞬时值不是最低配置要求。若 GUI 或其他运行实例正在使用，不应关闭他人的进程。

- 命令 ID `d472fc4a-044e-43f8-a4d4-6132f383a380`：对左侧索引 0 的 `shoulder_pan_joint` 下发绝对位置目标 −1.5400000525 rad；动作前测得 −1.5700000525 rad，目标按 +0.03 rad 构造。推进 60 步后测得 −1.5400391817 rad，速度约 0.0004033365 rad/s；这是一次组件动作，不是停止验证。

## 相机对照与复测

使用同一仿真进程、双臂和相机，保持 640×480 分辨率，每次调整后推进 15 步再读帧。用深度统计检查视野内是否有几何体，并检查 RGB 像素和实际取景。

| 条件 | RGB 范围 | 有限正深度像素数 | 结果 |
| --- | --- | ---: | --- |
| 原设置 | 0–0 | 20,425 | 取到几何深度，RGB 全黑 |
| 原视角补穹顶光 | 3–228 | 20,425 | 两只手可见，双臂上部出画 |
| 改朝向、光强设为 0 | 0–55 | 47,397 | 大部分画面仍然暗 |
| 改朝向并补光 | 3–228 | 47,397 | 亮度恢复，部分臂段仍出画 |
| 再拓宽镜头视野 | 4–228 | 10,577 | 两只手及臂段都进入画面，单个机器人占画面比例降低 |

无显式场景灯的原设置已有深度数据，保持原视角只补光就恢复了 RGB。采集脚本现在添加穹顶光，直接设置相机 prim 从 `[0, 3.6, 3.2]` 看向 `[0, 0.5, 0.6]`，并通过 Isaac Camera API 将焦距和水平孔径都设为 2.4。复测数据含实际相机位姿、渲染帧号和仿真渲染时间；RGB 缺失、全黑或均匀时通过 `rgb_status` 标记。仿真渲染时间和读取起止时间有各自的来源，尚未校准视觉时间与协调器时钟。

产物：[对照统计](runtime-io-camera-20261108/camera-comparison.json)、[正式入口复测 JSON](runtime-io-camera-20261108/sample.json)、[复测相机图像](runtime-io-camera-20261108/camera-rgb.png)。

## 入口

从仓库根目录使用已有固定环境启动器；输出目录是示例，可按实际情况更改：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\simulation\run_local.ps1 -Stage runtime-io -Headless -OutputRoot 'E:\Robotics\runtime-io-results'
```

此入口使用无窗口运行，依赖 Isaac Sim 4.5.0、DexGarmentLab、本地依赖及机器人资产。路径参数见 `run_local.ps1`。`-CheckOnly` 仅检查路径。组件采集和仿真 RGB 已在张电脑复测，控制闭环仍待实测。

脚本拟创建唯一目录并输出 `sample.json`，相机取到非空画面时另写 `camera-rgb.png`。它使用 DexGarmentLab 的双臂类、Isaac Sim 的 `dof_names` 和 `dof_properties` 按运行时索引读取信息，记录同一进程的 `time.monotonic_ns()` 和仿真时间/步数，给一次左臂单关节绝对位置目标分配 UUID，并在调用前后与推进步骤后读取双臂位置/速度。目标值由动作前实测读数加 0.03 rad 构成，并检查运行时报告的关节类型和限位。图片来自仿真相机，不是真实相机。

每次观察依次读取两臂关节，并记录起止时钟。此次复测中相机帧渲染于仿真时间约 1.483 s，读取时仿真时间约 1.533 s，两者相差约 50 ms 仿真时间。此差值来自单帧记录。相机标定和跨进程时钟同步仍待实测。

## 明确不覆盖

- 这是无衣物、非折叠组件探针，采用普通 `World`，不等同于 Fold Tops 的完整仿真和物理设置，不生成失败或恢复数据。
- `apply_action` 正常返回仅是本进程的 API 调用返回，脚本中 `adapter_ack` 保持 `null`；没有协调器的接收、去重、派发和 ACK，也没有代次屏障、取消、暂停或终止。
- 没有停止请求与静止判据，`stop_request` 和 `stop_feedback` 保持 `null`；速度读数不能单独证明安全停止。
- 没有完整实时相机标定、点云来源验证、衣物/接触重置、失败标签或恢复候选。抓偏、滑移、可比重置和恢复实验仍待实现并由胡审核标签。
- 系统适配器需按团队[接口契约](../../design/interfaces.md)继续实现和实测；此探针不是替代实现，不能向协调器声称其时钟已同步。
