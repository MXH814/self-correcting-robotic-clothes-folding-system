### 2.2 从文献到 gap 的证据规则

研究矩阵必须区分四种状态：作者明确讨论的限制、论文未测试的范围、我们实际复现的失败、我们已解释并改善的问题。

“未测试衣物”不等于方法不能用于衣物；“加历史/价值排序”不自动构成创新；换场景或组合已有模块也不能单独证明方法贡献。

阶段末至少选出 3 篇最近邻工作，逐项解释：同一问题上的输入、数据、动作、预算、目标和假设差异；为什么不能直接采用；应复现原方法、适配方法还是使用公开结果。不同环境的论文数值不得直接作为公平对照。

## 3. 候选研究问题与最小诊断

以下是待检验问题，最终只保留一条主线。首先验证问题是否真实存在，再决定网络结构。

### H1：衣物接触状态歧义是否需要历史信息

假设：相似当前观测可能对应不同的抓取/滑移过程，历史观测及已执行动作能够帮助选择不同恢复行为。

- 构造或筛选当前观测相似、接触经历不同的失败案例，记录相似性准则，避免只挑有利案例。
- 比较当前观测、观测历史、观测加动作历史；增加当前观测加任务阶段的对照，检查历史是否只是提供阶段信息。
- 尽量匹配训练数据、容量和预算；检查已有基线是否本就包含同等历史。
- 记录恢复选择和后续任务结果；只有分类改进不足以证明恢复更好。
- 否定条件：简单阶段条件或已有时序策略已经充分解决；优势源于额外信息泄漏、容量或数据规模。保留负结果并调整假设。

### H2：局部恢复质量与后续任务可完成性是否不一致

假设：重新抓稳的动作不一定有利于保留已完成折叠并继续任务，局部质量与后续结果可能存在冲突。

- 在同一开发失败状态下运行有限候选，比较局部抓取指标和后续任务结果。
- 先检查候选池是否存在成功动作；报告候选池最佳可达结果，区分生成不足和排序不足。
- 对照局部评分、简单任务条件价值评分和候选的随机/固定选择；算法复杂度由诊断决定。
- “后续成功概率”必须注明接续控制器、剩余预算和目标；不能当作与策略无关的固有标签。
- 否定条件：候选质量没有差异，或普通价值排序已经解决。此时不再叠加复杂预测网络。

### H3：失败数据的组织是否提高数据效率

备选假设：按失败机制采集比等量随机扰动或自然失败数据更有效。

- 匹配样本量、轨迹相关性、训练与采集成本，比较随机扰动、自然失败和机制组织数据。
- 留出未见扰动配置，防止仅学会识别注入模式。
- 否定条件：优势仅来自额外数据/计算，或只适用于训练扰动。

### 诊断数据与结果边界

初始以 30—60 个开发用失败状态为参考采集规模，覆盖两类失败及可实现的多个任务阶段；按成本调整并记录原因。该数量不是统计充分性保证，也不是正式测试规模。

数据按完整轨迹和衣物实例规划划分，关联分支留在同一集合。开发集上反复观察过的案例不得转称密封测试集。条件不足时不得宣称未见实例泛化。

仿真隐藏状态可用于离线标签、失败注入和诊断上限；进入在线算法的观测须有来源标识。使用特权状态的诊断必须与部署输入实验分开报告。

同状态候选实验需验证快照保存/恢复布料与接触的能力，不能只恢复关节角；若不支持精确恢复，采用可复现重置并量化起点误差。配对比较保留相同初态/扰动与方法顺序，记录仿真非确定性。

初步结果报告原始计数、配对差异、失败分类和不确定性。重复种子应预先安排；样本不足时结论限于探索，不通过反复尝试直至显著来选择结果。

### 6.1 架构建议与边界

以简单可替换的模块化结构作为候选：用户界面、任务协调器、仿真适配器、检测/恢复策略、记录与评价、离线训练/模型管理。优先评估单机模块化应用加独立仿真/推理进程，无实际需求不引入微服务或多智能体。

任务协调器独占运行控制权；策略提出有限动作，不直接绕过控制器执行。界面发送用户意图，不凭前端状态授予权限。仿真器与策略通过契约隔离，策略算法可替换。

架构模型需区分逻辑组件与实际进程/机器。GPU 实例、本地前端、日志存储和网络失联的影响必须明确；部署方案标明实测、设计假设和待验证项，P02 实测用于校正。

技术架构单独列语言、框架、平台、服务和模型，比较替代方案与选型理由；决定标记选定/暂定/延期。质量属性列优先级、冲突与设计机制，不能只重复 NFR 指标。至少一张系统级架构图配解释性叙述；领域/类与交互图表达关键用例如何实现。

AI 设计明确策略/协调/执行角色、工具接口、记忆和状态、编排、guardrails、人工监督及自主权限。按实际系统回答是否存在 LLM agent，不强行引入多智能体；Part III 使用 agentic development 与系统自身是否 agentic 分开说明。

### 6.2 必须设计清楚的不变量

1. 同一任务中人工和自主动作不能同时拥有控制权；收到停止请求不等于确认静止。
2. 请求 ID 与接受后的任务 ID 分离；重复 Start 不产生并发任务。
3. 动作带任务/控制代次和观测时间戳，旧结果、越界动作和无权限动作被拒绝。
4. 终止优先于暂停，暂停优先于策略；终态不被迟到结果覆盖；未解决停止仍阻塞新任务。
5. 暂停/接管不重置恢复次数和时间/费用预算；计费监控与动作派发独立。
6. 人工返回需要新停止证据与校验，失败后保持正确等待状态；UI 与后端使用同一状态含义。
7. 运行完成、离线质量、是否求助和自主成功分别保存；回放不能触发执行。
8. 模型/配置只能在允许的空闲条件切换，任务使用固定版本；拒绝和回滚保留旧版本。

### 6.3 数据与接口最低覆盖

数据设计至少覆盖任务/请求、事件与停止证据、观测/动作轨迹、恢复候选/决策、衣物与场景配置、模型与数据清单、试验记录、质量评价和用户操作。大文件引用与元数据分开；标明持久化方案、原子写入/中断恢复、访问控制、保留和删除规则。

接口设计至少覆盖任务创建/查询/控制、状态事件流、观测/动作、停止请求与证明、轨迹/结果读取、模型和配置版本。明确 sim time 与 wall time；记录点云来源、动作单位、坐标系、频率及延迟预算，不把隐藏 mesh 状态伪装成相机输入。

### 6.4 Design 的质量验证

- 三人用时序图走查正常、失败与恢复、暂停/返回、终止、失联和过期推理路径。
- 用 SRS 验收项构造契约/状态测试：正常请求、重复请求、非法状态、旧代次、停止超时、结果迟到与权限绕过。
- 性能、可靠性、安全/隐私、可维护性、成本和可用性逐项给出机制与验证方式；预算来自 SRS，实测失败时记录差距。
- 胡知鱼组织至少两名潜在用户进行设计走查，记录知情同意、匿名反馈和修改；与 SRS 正式运行可用性验收分开，走查不记为 T13 通过。
- 每个图示对应实际组件/对象/消息，连线、标签、异常分支清晰，文档、原型和模型同步。

## 8. 后续论文证据与风险

现有 SRS 的三方法×三条件×至少 20 次有效试验，共 180 次，是后续项目正式比较的最低计划；本阶段诊断不占用密封测试集，也不自动满足论文证据量。

论文实验将依据最终主张追加最近邻强基线、容量/数据/计算预算控制、多训练种子、消融、未见衣物/扰动泛化和失败边界。具体规模由试跑的波动、算力和论证需求确定，不预设一次探索结果足够发表。

无实体机器人不阻碍本阶段。若最终主张涉及真实接触/滑移可靠性，需尽早评估校内实验合作、硬件验证或替代证据，承认单环境仿真的边界。潜在导师/实验室反馈由团队自行安排，不因计划而自动联系外部人员。

主要风险及处理：环境不兼容则更换并记录；正常基线过弱则先修基线；注入不真实则补自然失败；候选无成功动作则优先改善生成；历史优势消失则停止该假设；任务差异造成比较不公则统一输入和预算；工程过重则优先最小闭环与契约，保留扩展接口。
